# Frictions — what is still wrong

Only open frictions live here. A row is removed the moment it closes, which is
the file's original policy and was ignored for four days: it reached 75 rows, 50
of them closed, and the closed ones were the majority of a document whose whole
job is to say what still needs doing. The removed rows are in git history, and
the reason each mechanism exists is written beside the mechanism, in the code
that implements it — which is where it is read.

`forge check` enforces both halves of that: a row marked closed must not still be
here, and no file may cite a friction number this table no longer has.

**What the statuses mean.** They were vague enough that a sentence in a document
counted as a fix, so they are now a fixed vocabulary:

| Status | Means |
|---|---|
| `open` | nothing has been built; a proposal may exist |
| `partial` | some of it is closed by evidence, and the row says exactly which part is not |
| `blocked` | the fix is known and needs a decision or a permission that is not mine |

A friction closes by **mechanism** (something now fails when the problem
recurs), by **evidence** (it was executed and observed), or by **removal** (the
thing that could fail is gone). It does not close by being described, and it
does not close by being reported closed — row 12 sat marked closed while the
exposure it describes was live.

# Review: a dead store must not render as a live empty dashboard

One fresh-context adversarial round on a three-file diff (serve.py 404
disambiguation, verify.sh deterministic store tests + narrowed user-scope
check, the first-ever captured SessionStart fixture), plus nits folded in and
re-verified. Verdict: APPROVE WITH NITS; every nit addressed before recording:
the probe is now ref-aware (/branches/{branch}, so a typo'd branch cannot be
blessed as "honestly empty"), the retained listing ETag is cleared on the
confirmed-empty path, record.py's stale "SessionStart has never been observed"
comment now tells the truth, and the user-scope ok-message no longer names a
file that may not exist.

The reviewer proved the load-bearing part empirically: with the serve.py fix
stashed, the stubbed (404,404) test fails with exactly the observed bug
signature ({"source": "store", "waiting": []}) and recovers on restore. It
verified the stub signature matches the real _api seam, that the (404,200)
case guards the opposite over-correction, that the narrowed section-8 check
still catches hand-wired hooks while allowing enabledPlugins, and that fold()
consumes the fixture's `source` field. Known accepted limits, flagged by the
reviewer: the probe is uncached (more rate-limit spend while a store is empty),
and the user-scope scan reads only settings.json's hooks key, so a monitor
wired into another executing key (e.g. statusLine) would pass - the same blind
spot the old grep had, minus its false positive.
